Pattern Recognition and Abstraction at Project Scale

Previous Course Home Next Lesson
100 minutes Phase 1 · Computational Thinking Foundations Finding Patterns, Building Models

Why This Matters

Look closely at a leaf. The veins repeat the same branching pattern again and again. Nature uses patterns because they are efficient and beautiful. In computational thinking, patterns help you design better systems, and abstraction helps you simplify what you see into a clear model.

Together, these two pillars turn a messy, complicated project into something clear and buildable.

What You Will Learn

  • Identify patterns in user needs and data.
  • Create an abstract model of a project.
  • Use your model to simplify the design.

Words to Know

pattern pattern recognition abstraction model architecture data flow simplification

Lesson Journey (100 minutes)

Part 1 — Finding Patterns 0–10 min

Read these user behaviours:

  • Users borrow books on Monday and return them on Friday.
  • Users search by genre.
  • Users recommend books to friends.

What patterns do you see? Patterns help us design better systems because we can predict what users will do.

Part 2 — Abstraction as Modeling 10–30 min

Abstraction at project scale means creating a model of the whole system. There are three main models you will use this year:

  • Architecture diagram — shows the components and how they connect.
  • Data flow diagram — shows how data moves through the system.
  • User flow diagram — shows what the user does, step by step.

Example — Automatic plant control system:

  • Architecture: sensor → controller → pump → user interface.
  • Data flow: soil moisture reading → decision → pump command → log entry.
  • User flow: open app → view moisture → set threshold → receive alert.

Part 3 — Practise Together: Library System 30–55 min

Let's build three models for the library system together:

  • Architecture diagram: database, recommendation engine, user interface, borrowing history.
  • Data flow: user searches → engine queries database → results ranked → displayed.
  • User flow: log in → search → view recommendations → borrow.

Draw on the board together.

Part 4 — Your Turn: Model Your Project 55–85 min

Create three models for your project:

  • An architecture diagram.
  • A data flow diagram.
  • A user flow diagram.

Then identify patterns in your data or user behaviour.

Part 5 — Share and Discuss 85–95 min

Present your models to the class.

Discuss: How does abstraction make the project easier to design?

Part 6 — Exit Ticket 95–100 min

Draw one model of your project and explain what it simplifies.

Check Your Understanding

You are ready to move on when you can create architecture, data flow, and user flow models.

Support: Use model templates with labelled boxes.

Challenge: Can you identify potential bottlenecks in your model?
