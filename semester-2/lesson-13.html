Creating a Test Plan

Previous Course Home Next Lesson
100 minutes Phase 9 · Testing & Iteration Test Cases, Coverage

Why This Matters

Testing finds problems before your users do. A test plan helps you check every part of your system — normal cases, edge cases, and invalid inputs. This is how professional software is built.

What You Will Learn

  • Create a test plan.
  • Write test cases for normal, boundary, and invalid inputs.
  • Execute tests and record results.

Words to Know

test plan test case normal case boundary case invalid case expected result actual result

Lesson Journey (100 minutes)

Part 1 — Why Test? 0–10 min

Ask yourself: Why do we test software?

  • To find bugs.
  • To ensure quality.
  • To improve user experience.

Testing finds problems before users do.

Part 2 — Test Plan 10–30 min

Test plan structure:

  • Test case ID.
  • Description.
  • Input.
  • Expected output.
  • Actual output.
  • Pass/Fail.
  • Notes.

Three types of test cases:

  • Normal: typical input.
  • Boundary: edge values.
  • Invalid: bad input.

Example:

  • T1 — Search for a book — "Harry" — List of books — List shown — Pass.
  • T2 — Search empty — "" — Error message — No message — Fail.

Part 3 — Write Test Cases Together 30–55 min

Write 10 test cases for the library system.

Part 4 — Your Turn: Create Your Test Plan 55–85 min

Create a test plan:

  • At least 10 test cases.
  • Include normal, boundary, and invalid.
  • Execute and record results.

Part 5 — Share and Discuss 85–95 min

Present your test plan.

Discuss: What bugs did you find?

Part 6 — Exit Ticket 95–100 min

Write one normal, one boundary, and one invalid test case.

Check Your Understanding

You are ready to move on when you can create and execute a test plan.

Support: Use a test plan template.

Challenge: Automate your tests.
